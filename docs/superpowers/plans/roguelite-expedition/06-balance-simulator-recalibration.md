# Balance Simulator Recalibration and Evidence Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Recalibrate the shipped Expedition loop using six fully explicit production-valid strategies, disjoint calibration/holdout cohorts, linked Career sequences, paired extraction/skill probes and real runtime evidence.

**Architecture:** The simulator orchestrates the same G1–G5 production builders/resolvers used by the app. It may choose decisions according to deterministic profile policies but may not duplicate production formulas. Single-run cohorts measure run balance; linked Career cohorts measure meta/Nemesis/unlock timing; real playtest telemetry measures actual elapsed time.

**Tech Stack:** Node ESM scripts, TypeScript production imports, deterministic seeded RNG, existing v14/v15 report infrastructure, Node tests and Playwright/runtime instrumentation.

## Task 4: Build each simulation loadout through production owners only

```js
export const buildProductionSimulationLoadout = (
  linkedState,
  profile,
  seed
) => validatedActiveState
```

Exact sequence:

1. Start from `createInitialState()` or the linked Career state supplied by Task 11.
2. Seed **only** the profile's required unlock-set markers/eligibility through production-compatible fixtures; record every seeded marker in provenance.
3. If `requiresAscension`, seed/derive `career.ascensionUnlocked:true` through the late-career fixture path used by production tests.
4. Ensure the profile chassis exists through the production `purchaseChassis`/asset fixture path with exact `{ kind:'tourbus_chassis', flavor, tier }`; select it as active.
5. Ensure each `requiredModuleId` is unlocked/owned and install it through production `INSTALL_MODULE`; any failure throws.
6. Select Crew by `crewRoleOrder` through `isCrewAvailable`, exact three-or-fewer ids; absence throws.
7. Apply `equipmentPolicy`: `current_snapshot` uses current equipment; `best_owned` equips deterministic best legal owned gear by production equip action (descending canonical quality/value, lexical id tie break) before Prep.
8. Apply `setlistPolicy` to already-owned/currently legal songs only:
   - `balanced_four`: deterministic spread around median difficulty/energy;
   - `lowest_difficulty_four`: ascending difficulty then id;
   - `highest_energy_four`: descending energy then id.
   Use first four legal unique songs; if fewer than required by production, throw.
9. Call G1 `PREPARE_EXPEDITION_RUN` with the profile seed; assert status becomes `prepared`.
10. Build the prepared map from that exact seed.
11. Apply `sponsorPolicy` using real `generateBrandOffers` + accept flow:
    - `none`: accept none;
    - `highest_clean_value`: among eligible non-controversial offers, highest canonical payout/value then lexical id;
    - `highest_exposure_value`: highest offer tagged/derived for Exposure/high-profile value then payout/id;
    - `highest_nonrival_value`: exclude offers removed/interfered by current Rival rules, highest remaining payout/id.
12. Build native Contract offers from the G4 registry against the prepared map in the listed preference order; accept every legal preference until production Contract-slot limit; route target identity is preserved.
13. Materialize cargo using exact deterministic policy:
    - `safe`: 2 spare parts, 2 supplies, no merch/Contraband;
    - `balanced`: 2 spare parts, 2 supplies, first legal merch stack by lexical key, no Contraband;
    - `merch`: 1 spare part, 1 supply, fill remaining legal capacity with merch by lexical key;
    - `contraband`: 2 spare parts, 1 supply, first legal Contraband instance by lexical `{stashKey,instanceId}`, then merch with remaining capacity.
    If fixture ownership is insufficient, seed inventory/stash through existing test fixture/setup owner and record it; never invent unknown ids.
14. Set exact `startingFuelTarget` from profile; require it is >= current Fuel and affordable.
15. Set `protectedCareerCash = floor(player.money * profile.protectedCashRatio)`; ensure START costs remain spendable, otherwise fixture setup is invalid and throws.
16. Set insurance id, starter perk and pressure ids exactly from profile.
17. Call the one G1 `validateExpeditionLoadout(state,candidate)`.
18. Dispatch production `START_EXPEDITION`; assert `status === 'active'` and every commitment equals the resolved provenance snapshot.

There are no fallback profile defaults. Any invalid step throws with profile id + failing production validator reason.

## G6 Exit criteria

- Six strategies are concrete objects, not names/interfaces; every committed build axis has an explicit policy/value.
- Every profile resolves through production chassis/module/Crew/setlist/equipment/Sponsor/Contract/cargo/Fuel/Cash validation or throws.
- Resolved complete loadouts/provenance are serialized, so calibration and holdout cannot hide different defaults.
- Main calibration/holdout are 2,000 runs/profile with disjoint seeds.
- Extraction probe has separate disjoint calibration/holdout populations.
- Skill probe holds management snapshot fixed and exercises production Crowd-Hype/Condition/Injury/Finale/repair mechanics.
- Meta/Nemesis/quest/HQ timing comes from linked six-run Career sequences, not isolated runs.
- Fresh-career run-1 Expedition-affecting legacy HQ purchase rate is exactly zero under the G5 policy.
- Chassis **and exact module/Crew combinations** are included in dominance evidence.
- All five Legendary capabilities have real production activation evidence.
- 20–30 minute target is evaluated only from real runtime samples and remains soft until sample threshold is met.
